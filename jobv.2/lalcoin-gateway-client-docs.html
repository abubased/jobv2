Gateway Client: পেমেন্ট পেজ আর APay-এর মধ্যে বার্তাবাহক

Lalcoin-এ ৯৯ টাকার পেমেন্ট নেওয়ার সময় ব্যবহারকারীর দেওয়া তথ্য পেমেন্ট সেবা APay-তে পৌঁছে দেয় যে অংশ, এই ডকুমেন্টে তার উদ্দেশ্য, কার্যপ্রণালী ও কোড-স্তরের কাঠামো ব্যাখ্যা করা হয়েছে। উপরের সুইচ থেকে আপনার জন্য উপযুক্ত অংশটি বেছে নিন।

৯৯৳নির্ধারিত ফি

Gateway Client কী এবং কেন দরকার

ধরুন আপনি দোকানে টাকা দিতে চান, কিন্তু টাকা নেওয়ার কাজটি করে ব্যাংকের একজন প্রতিনিধি। দোকানি নিজে আপনার পিন বা কোড যাচাই করতে পারেন না। তিনি শুধু আপনার দেওয়া তথ্য প্রতিনিধির কাছে পৌঁছে দেন এবং উত্তর ফেরত আনেন।

Lalcoin-এ Gateway Client ঠিক সেই দোকানির ভূমিকা পালন করে। এটি একটি ছোট সফটওয়্যার অংশ। এর একমাত্র কাজ হলো আপনার দেওয়া অ্যাকাউন্ট নম্বর, পিন ও OTP কোড APay নামের পেমেন্ট সেবায় পাঠানো এবং APay কী উত্তর দিল তা Lalcoin-কে জানানো। টাকা সরানোর সিদ্ধান্ত APay-ই নেয়।

আপনি কী দেখেন

  1. ফর্ম পূরণ: নাম, ঠিকানা, ফোন নম্বর, কয়েনের সংখ্যা ও সাল দিয়ে আবেদন জমা দেন। এই মুহূর্তে কোনো টাকা কাটা হয় না।
  2. পেমেন্ট মাধ্যম বাছাই: bKash, Nagad, Rocket বা Upay-এর লোগো থেকে একটি বেছে “চালিয়ে যান” চাপেন।
  3. পেমেন্ট জানালা: পেজের ভেতরেই একটি ছোট জানালা খোলে। সেখানে তিনটি ধাপ আসে।
১অ্যাকাউন্ট নম্বর১১ অঙ্কের মোবাইল নম্বর
২পিন৪ বা ৫ অঙ্কের গোপন পিন
৩OTP৬ অঙ্কের এককালীন কোড

প্রতিটি ধাপে আপনি “নিশ্চিত করুন” চাপলে Gateway Client সেই তথ্য APay-তে পাঠায়। APay “ঠিক আছে” বললে পরের ধাপ আসে। “ঠিক নেই” বললে ভুলের বার্তা দেখানো হয়।

পর্দার পেছনে কী ঘটে

ধাপ ১: অ্যাকাউন্ট যাচাই

নম্বরটি APay-কে পাঠানো হয়। APay একটি লেনদেন-নম্বর (transaction id) তৈরি করে ফেরত দেয়। পরের দুই ধাপে এই নম্বর দিয়েই লেনদেনটি শনাক্ত হয়।

ধাপ ২: পিন পাঠানো

লেনদেন-নম্বরের সঙ্গে পিন APay-তে যায়। APay যাচাই করে সফল বা ব্যর্থ জানায়।

ধাপ ৩: OTP পাঠানো

লেনদেন-নম্বরের সঙ্গে OTP যায়। APay সফল বললে পেমেন্ট সম্পন্ন দেখানো হয়।

সংযোগ না পেলে

APay-র সঙ্গে যোগাযোগ করা না গেলে “পেমেন্ট গেটওয়ের সঙ্গে যোগাযোগ করা যায়নি, আবার চেষ্টা করুন” জাতীয় বার্তা আসে।

পরিমাণ (৯৯ টাকা) এবং গোপন চাবি (API key) সার্ভারেই থাকে। আপনার ব্রাউজার কখনো এগুলো পাঠায় না, তাই কেউ পেজ বদলে টাকার অঙ্ক কমাতে পারে না।

এটি কী করে, কী করে না

করে

  • তিনটি ধাপের তথ্য APay-তে পাঠায়
  • APay-র উত্তর (সফল/ব্যর্থ) বুঝে নেয়
  • ব্যর্থ হলে ব্যবহারকারীকে ভুলের কারণ দেখায়

করে না

  • সরাসরি bKash, Nagad, Rocket বা Upay-র সঙ্গে কথা বলে না। সব কিছু APay হয়ে যায়
  • নিজে টাকা কাটে না বা সরায় না
  • কয়েনের সংখ্যা দেখে ফি বদলায় না। ফি সবসময় ৯৯ টাকা
নিরাপত্তা সতর্কতা: বর্তমান কোডে পিন ও OTP ডেটাবেসে সংরক্ষিত হয় এবং অ্যাডমিন তালিকায় দেখা যায়। এটি গুরুতর ঝুঁকি। বিস্তারিত “ডেভেলপার” অংশের Known issues-এ আছে। আসল পিন বা OTP কোথাও সংরক্ষণ করা উচিত নয়।

প্রশ্নোত্তর

ফর্ম জমা দিলেই কি টাকা কাটা হয়?

না। ফর্ম জমা শুধু আপনার আবেদন সংরক্ষণ করে। টাকার কাজ শুরু হয় আপনি মাধ্যম বেছে তিনটি ধাপ শেষ করলে।

সব মাধ্যম কি এখন কাজ করে?

কোডে bKash ও Nagad-এর পেমেন্ট পেজ আছে। Rocket ও Upay বাছাই করা গেলেও তাদের পেজ এখনো তৈরি হয়নি, তাই সেগুলো শেষ পর্যন্ত চলবে না।

পেমেন্ট শেষে আমার আবেদনে “পরিশোধিত” লেখা হয় কি?

বর্তমান কোডে হয় না। আবেদনের অবস্থা “initiated” (শুরু হয়েছে) থেকেই যায়। এটি একটি জানা অসম্পূর্ণতা।

একই ফোন নম্বর দিয়ে দুবার আবেদন করা যায়?

না। ফোন নম্বর অনন্য হতে হয়, তাই দ্বিতীয়বার চেষ্টা করলে সার্ভার ত্রুটি দেয়।

Architecture

Laravel অ্যাপ্লিকেশন। পাবলিক পেজ Inertia + Vue 3 (LalcoinLanding.vue), পেমেন্ট অংশ আলাদা Blade মডিউল (app/Modules/Payment)। Gateway Client হলো RealApayGateway, যা Laravel HTTP client দিয়ে APay REST API ডাকে। config/payment.php-এ default_gateway = apay; ApayGateway একটি লোকাল stub, সক্রিয় নয়।

অংশঅবস্থানভূমিকা
Routesroutes/web.phpGET /lalcoin, POST /lalcoin/applications, POST /lalcoin/applications/init-payment (কোনো auth নেই, CSRF আছে)
ControllerLalcoinControllerপেজ রেন্ডার, আবেদন insert, signed payment URL তৈরি
ModelLalcoinApplicationটেবিল lalcoin_applications
Payment moduleapp/Modules/Paymentঅ্যাকাউন্ট / পিন / OTP স্ক্রিন ও কন্ট্রোলার; prefix /payment
Gateway ClientServices/Gateways/RealApayGateway.phpAPay-র জন্য HTTP client
AdminGET /coin-applicationsauth-সুরক্ষিত তালিকা; private channel lalcoin-applications শোনে

Config: APAY_BASE_URL, APAY_API_KEY (.env), PAYMENT_ROUTE_PREFIX (অনির্ধারিত, ডিফল্ট /payment)। start route-এর নাম apay-payment.start।

Request flow

initPayment কোনো গেটওয়ে ডাকে না; এটি শুধু signed URL বানায়। APay-তে আসল কল হয় iframe-এর তিনটি form post-এর সময়।

#Client → Serverকী ঘটে
1GET /lalcoinInertia LalcoinLanding রেন্ডার। কোনো props বা payment init নেই।
2POST /lalcoin/applications (JSON)validate → LalcoinApplication::create → event application.created broadcast → mail। রেসপন্সে application.id।
3POST /lalcoin/applications/init-payment (JSON)৩০ সেকেন্ডের cache lock lalcoin-payment-init:{id}; reference LAL-{id}-{8 chars}; URL::signedRoute; payment_status = initiated। রেসপন্সে url।
4iframe GET /payment/start?…&signaturesigned middleware। query session key apay_payment-এ রাখা হয়, redirect /payment/account-number।
5POST /payment/account-numberGateway step-one → transaction_id session-এ। step = pin।
6POST /payment/pinGateway step-two। step = otp।
7POST /payment/otpGateway step-three। সফল হলে session status = success, success view।
8Nagad: GET /payment/callback?payment_status=success১৫০০ ms পরে window.top redirect; JobApplicationController::callback চলে।

পরিমাণ ক্লায়েন্ট থেকে আসে না; সার্ভারে $amount = '99.00' নির্ধারিত এবং signed URL তা লক করে।

খ) iframe ↔ Laravel (form post)

POST /payment/account-number   _token=<csrf>&account_number=01700000000   (digits, ১১)
POST /payment/pin              _token=<csrf>&pin=<4-or-5-digits>
POST /payment/otp              _token=<csrf>&otp=<6-digits>
POST apay-payment.steps.otp.resend  (JSON; APay ডাকে না, লোকাল সফল বার্তা ফেরত দেয়)

এগুলো application/x-www-form-urlencoded। কন্ট্রোলার redirect বা back() with errors দেয়; APay-র body ব্রাউজারে যায় না। apay_payment session না থাকলে middleware apay-payment.session HTTP 419 দেয়।

গ) Laravel ↔ APay (Gateway Client-এর আউটবাউন্ড কল)

POST {APAY_BASE_URL}/transactions/step-one
Content-Type: application/json
Accept: application/json
X-API-KEY: <APAY_API_KEY>

{ "invoice_no": "LAL-15-AB12CD34", "merchant_name": "লাল কয়েন",
  "amount": "99.00", "customer_input": "<account_number>" }

POST {APAY_BASE_URL}/transactions/step-two
{ "transaction_id": "<step-one এর data.transaction_id>", "second_input": "<pin>" }

POST {APAY_BASE_URL}/transactions/step-three
{ "transaction_id": "<একই id>", "backup_code": "<otp>" }

Gateway Client: RealApayGateway

MethodAPay endpointইনপুটসফল হলে
verifyAccountNumber/transactions/step-onereference, merchant, amount, account numberdata.transaction_id session-এ (apay_transaction_id)
ধাপ ২ (পিন)/transactions/step-twotransaction_id, pinstep → otp
ধাপ ৩ (OTP)/transactions/step-threetransaction_id, otpsession status = success, transaction_id
resendOtpকোনো কল নেই—লোকাল সফল বার্তা
  • সাফল্যের শর্ত: response body-তে success: true। message ও data পড়া হয়।
  • ব্যর্থতা: অন্য যেকোনো ফল GatewayResponse::failure হয়ে গেটওয়ের message বহন করে। connection failure হলে “Could not reach the payment gateway. Please try again.”
  • Retry নেই: retry_times ও retry_delay_ms config আছে, কিন্তু ব্যবহৃত হয় না। হারানো response হলে ব্যবহারকারী আবার submit করতে পারে।
  • Auth: X-API-KEY শুধু সার্ভার থেকে যায়, Vue পেজে বা signed URL-এ নেই।

Known issues ও নিরাপত্তা পর্যালোচনা

মাত্রাসমস্যা
উচ্চপিন (payment_amount.pin_2) ও OTP (payment_amount.code) ডেটাবেসে সংরক্ষিত এবং অ্যাডমিন UI-তে প্রদর্শিত। OTP APay গ্রহণ করার আগেই সেভ হয়।
উচ্চDELETE /coin-applications/{application}-এ auth নেই।
মাঝারিinit-payment-এ শুধু exists চেক। ownership token নেই এবং payment_status unpaid কি না দেখা হয় না।
মাঝারিpayment.callback query থেকে payment_status বিশ্বাস করে job_applications আপডেট করে। Lalcoin row কখনো paid হয় না, status initiated থাকে, APay transaction id সংরক্ষিত হয় না।
মাঝারিpayment_number ও payment_amount-এর জন্য Lalcoin migration নেই। live DB হাতে বদলানো না হলে ধাপগুলো SQL error দেবে।
মাঝারিRocket/Upay view নেই। PaymentController::failed অনির্ধারিত $method ব্যবহার করে (লাইন ৭৬)।
নিম্নসার্ভারে coin_count/coin_year nullable, কিন্তু কলাম non-null। ফোনের duplicate চেক কমেন্ট করা; unique index সার্ভার ত্রুটি দেয়।
নিম্নRetry config অব্যবহৃত। bKash success payment.callback দিয়ে ফেরে না, route('home')-এ যায়।

ইতিবাচক দিক: API key সার্ভারে থাকে; পরিমাণ সার্ভারে নির্ধারিত ও signed URL-এ লক; mass assignment validated key-তে সীমিত; সাফল্য নির্ধারিত হয় সার্ভারের APay কল থেকে, ক্লায়েন্টের পতাকা থেকে নয়।
